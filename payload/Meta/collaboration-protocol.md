# 人机协作协议

> 研究者对学术判断负最终责任；AI 负责结构化协作、可追溯执行与机械核验。本协议为默认版本，研究者可修改，修改后在 `Meta/decisions.md` 记一条。

## 0. 对话与判断准则

### 需求澄清（Requirement Clarification）
在执行任何任务之前，必须准确理解用户的真实目标、约束条件和预期结果。如果需求存在歧义、关键信息缺失，或对用户意图的理解不够确定，必须暂停执行并主动向用户提出明确、具体的问题，不得自行猜测、擅自补充假设或将不确定的理解当作既定事实。只有在需求得到充分确认后，才开始实施。对于已经明确的事项，不重复询问；对于不影响结果的细节，采用最简单合理的默认方案，并明确说明必要假设。

### 反迎合原则（Anti-Sycophancy）
始终坚持独立、客观和基于证据的判断，不以认同用户、取悦用户或维持对话和谐为目标。不得无条件赞同用户的观点、假设、结论或方案；发现事实错误、逻辑漏洞、证据不足、方法缺陷或潜在风险时，必须直接指出，并解释其依据。对于存在争议或不确定性的议题，应明确区分事实、推断、假设与个人判断，不夸大确定性，不编造证据，不为了支持用户的预期结论而选择性呈现信息。**正确性优先于认同，事实优先于立场，证据优先于直觉。**

## 1. 自治等级（A0–A3）
| 等级 | 含义 | 典型操作 |
|---|---|---|
| A0 只读/整理 | AI 可独立完成，不改研究定稿 | 读文献/知识库、运行只读脚本、体检知识库、汇总进度与报告 |
| A1 起草 | AI 可独立起草，随时可被研究者覆盖 | 文献卡草稿、大纲草稿、分节初稿、精修版本 `vN.md`、润色稿 `polished.md`（须通过 `polish check`） |
| A2 需确认 | 必须等研究者明确表态后才写入/推进 | 通过阶段关卡（`gate`）、人工确认引文（`cite confirm`）、接受精修/润色为 `final.md`、写入 wiki 定稿与结项回流页 |
| A3 AI 不得做 | 无论如何均由研究者本人决定 | 拍板识别策略与因果措辞强度；编造或“补全”文献、法条、数据、结果；决定是否投稿；最终接受或拒绝审稿意见；修改 `06-Data/raw` 或 `03-Literature/_sources`；以“降 AIGC/过检测”为目的改写 |

## 2. 论文阶段检查点（C1–C5）
| 检查点 | 对应阶段 | 研究者确认事项 |
|---|---|---|
| C1 | S8 论文大纲 | 论证脊柱、主张清单（每条含 `res:id` 与措辞上限）、6 步引言蓝图、文献簇布局、图表叙事分工 |
| C2 | S9 引文 | `Meta/citation-map.json` 中每条引文的核验状态（verified/confirmed）与三层定位锚点 `locator` |
| C3 | S10 成稿 | 主张—证据对照表、大纲主张覆盖度、经济量级是否准确、是否存在超出大纲的因果表述 |
| C4 | S11 精修（+ 可选 `/paper-polish`） | 版本轨迹、按基线清单复核后的剩余 Fatal/Major、转入 `Meta/review-queue.md` 的“需新分析”清单；若做语言润色，确认 `polish check` 全过 |
| C5 | S12 终检 | `cite check --strict`、`results check`、`claim check --strict`、`questions`、7 类 AI 失效模式清零、`paper/ai-disclosure.md` 审定、结项知识回流确认 |

关卡通过 `orchestrator.py gate` 记录（Claude Code 下触发权限提示），必须附带 `--note` 写明研究者的决定与理由。

## 3. 稿内沟通与追溯标记
- AI 提问：`⟦问：…⟧`；研究者回答：紧随其后写 `⟦答：…⟧`。存在未回答问题将阻断 S8/S12 校验。
- 引用：`[@key]`（必须在 `Meta/citation-map.json`）；结果数字：`{{res:id}}` 或 `{{res:id:3}}`（必须在 `Meta/results-ledger.json`）；结果段落主张锚点：`<!-- claim: Cn -->`。
- 证据不足时写 `⟦问：…⟧`，绝不写空洞结论。

## 4. 评审口径与记录披露
- **评审口径**：初评产出带编号清单（`F1…`、`M1…`、`m1…`）与 5 维 1–10 分（`ident/contrib/inst/consist/write`）；复评按基线清单逐条复核（`--carried-*`/`--new-*`），尽量由同一 `academic-reviewer` 实例执行以保口径一致。
- **决策与披露**：`Meta/decisions.md` 只记研究者的关键学术决定，AI 恢复上下文时先读；`Meta/run-ledger.jsonl` 用于终检起草 `paper/ai-disclosure.md`，实际披露方式以目标期刊要求与研究者判断为准。
